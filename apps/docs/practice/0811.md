## 기억 복구

1. openValue는 누가 소유하는가?

-> ~~AccordionContent 자기 자신이 소유하고 있다. openValue 소유한 사람에 따라 내용이 다르다.~~
**Accordion이 소유해. Content는 소유자가 아니라 소비자야.**

2. Context는 상태를 소유하는가? 무슨 역할인가?

-> 상태를 소유하는 것이 아니라 **값을 전달하는 통로** 역할

3. AccordionContext에는 무엇이 들어가는가?

-> ~~전체 아코디언의 내용이 들어가 있고 어떤 것을 클릭했는지 볼수 있는 toggle 함수가 들어있다~~
**openValue와 toggle 같은 AAccordion 전체에서 공유해야 하는 값/함수가 들어있다.**

4. AccordionItemContext에는 무엇이 들어가는가?

-> ~~AccordionItem이 가지고 있는 내용이 들어있다.~~
**현재 Item의 식별값(value)같은, 그 Item 범위에서 필요한 저옵가 들어있다.**

5. 왜 Context가 2개인가?

-> 전체를 알아야 하는 경우 한개와 각자가 다른걸 가지고 있는 경우가 다르기 때문에 두가지가 필요하다.
하나는 전체 Accordion 범위의 정보 하나는 현재 Item 범위의 정보라서 분리된 거.

6. 클릭부터 Content가 열릴 때까지 흐름을 써보자.

Trigger
-> onClick() => toggle
-> 전체 내용 파악
-> 자기꺼랑 비교해서 맞으면 열고 아니면 닫는다
Content

Trigger
-> Trigger가 AccordionItemContext에서 자기 value를 읽음.
-> Trigger가 ACcordionContext에서 toggle을 읽음.
-> toggle(value) 호출
-> Accordion의 openValue가 변경됨.
-> Content가 AccordionContext의 openValue를 다시 읽음.
-> Content가 AccordionItemContext의 자기 value와 비교
-> 같으면 렌더, 아니면 숨김.
Content
